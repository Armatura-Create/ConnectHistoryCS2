# Модуль для Flute CMS

Данные плагина показывает готовый модуль панели —
**[ConnectHistory-Flute](https://github.com/Armatura-Create/ConnectHistory-Flute)**.
Писать свой не нужно; этот документ объясняет, как их связать и почему связка
устроена именно так.

Раньше здесь лежал учебный пример модуля. Он устарел: Flute переехал на
`Flute\Core\ModulesManager\ModuleInformation` и `Cycle\Database\Injection\Parameter`,
а админ-панель получила слои `Filters`, `Table`, `Metric` и `Chart`, поверх которых
такой модуль пишется иначе. Актуальный код — в репозитории модуля.

## Установка

1. Скачайте архив со [страницы релизов](https://github.com/Armatura-Create/ConnectHistory-Flute/releases)
   и распакуйте в `app/Modules/` панели.
2. Админ-панель → Модули → активировать **ConnectHistory**.
3. Админ-панель → Серверы → нужный сервер → добавить подключение к базе,
   тип подключения — **ConnectHistory**.
4. В настройках подключения указать **ServerId** — то же число, что стоит в
   `Settings.json` плагина на этом сервере, и **префикс таблиц**, если он не `ch_`.

Готово: разделы «История» появятся в меню панели.

## Права

| Право | Что открывает |
|---|---|
| `admin.connecthistory` | Просмотр всех разделов истории |
| `admin.connecthistory.pii` | Колонки `player_ip`, `city`, `ip_subnet` и поиск мультиаккаунтов по `ip_hash` |

Второе право — не «показать скрытую колонку»: без него персональные поля
не попадают в текст `SELECT`. Утечь через интерфейс им физически неоткуда.

## Пользователь базы

Панели запись в историю не нужна:

```sql
CREATE USER 'ch_reader'@'%' IDENTIFIED BY '...';
GRANT SELECT ON connect_history.* TO 'ch_reader'@'%';
```

## Несколько серверов

Плагин различает серверы колонкой `server_id` внутри **одной** базы, поэтому
подключение к ней заводится для каждого сервера панели отдельно, и в настройках
каждого указывается свой `ServerId`. Имя базы при этом одно и то же.

Фильтр «Сервер» в разделах истории собирается из этих привязок.

## Если решили писать свой модуль

Всё, что нужно знать про данные, — в [DATABASE.md](DATABASE.md): схема, смысл
колонок и готовые запросы. Три вещи, на которых спотыкаются чаще всего:

- **Время в базе — UTC.** Сравнивать с «сейчас» нужно через `UTC_TIMESTAMP()`,
  а не `NOW()`: второй отдаёт время в поясе сессии MySQL.
- **`steamid64` — строка.** 64-битное число теряет точность в PHP int на 32-битной сборке.
- **Считайте агрегаты в SQL.** Выборка сырых сессий за длинный период кладёт панель:
  стоимость страницы не должна зависеть от объёма накопленной истории.

Разбор восьми ошибок, на которых сломался предыдущий модуль панели, —
[docs/AUTOPSY.md](https://github.com/Armatura-Create/ConnectHistory-Flute/blob/main/docs/AUTOPSY.md)
в репозитории модуля.
